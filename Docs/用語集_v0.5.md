## 1. 使い方
- 用語は、本書の定義に合わせて使う。新しい用語は、本書に定義を追加してから使う
- 用語 ID（`GLS-xxx`）は一度付けたら変更・再利用しない
- 2〜8章の定義は、要件定義書に書かれた内容だけを根拠とする。要件定義書に定義がないものは `TBD:` として残す
- 9章の定義は、要件定義書にない開発・実装上の用語である。根拠は、設計書と実装計画書の記述とする
- 「参照」列は、定義の根拠となる要件定義書・設計書・実装計画書の ID または章を示す

| GLS-021 | 給与体系 | 通常評価制度／年俸制／単価連動（19期のみ） のいずれか | `REQ-DAT-008` |

| GLS-024 | 単価連動 | 19期のみの給与体系。計算ルールは取り込まない | `REQ-DAT-008`、`REQ-MIG-004` |

| GLS-026 | 改定区分 | 給与履歴を追加した理由。定期（4月）／定期（10月）／年俸改定（4月）／制度移行／入社／その他 | `REQ-DAT-008` |
| GLS-027 | 給与項目 | 月給や手当の項目。自由に追加・変更できる。区分は基本給／固定支給／一時手当 | `REQ-DAT-004` |
| GLS-028 | 手当 | 基本給以外の給与項目。固定支給と一時手当を含む | `REQ-DAT-004` |
| GLS-029 | 月給合計 | 給与履歴の内訳の合計。保存せず、計算で求める | `REQ-DAT-009` |
| GLS-030 | 月給の外の手当 | 月給に含めず、原価にそのまま加算する手当（`cost_direct`） | `REQ-DAT-004`、`REQ-CAL-012` |
| GLS-031 | 減額順 | 減額するときに、給与項目から差し引く順番。リーダー→資格→その他→一時→役職→住宅→固定残業。減額順のある項目の合計を超える分は、基本給から差し引く | `REQ-DAT-004`、`REQ-CAL-006` |
| GLS-032 | 昇給 | 前の履歴との月給合計の差。自動で計算し、専用テーブルは作らない | `REQ-DAT-009`、`REQ-FUN-004` |
| GLS-033 | 評価ランク | 賞与の掛け率を決める評価の区分。S／A／B／C／D の 5 段階。評価は20期上期から管理する | `REQ-DAT-007`、`REQ-DAT-010` |

## 5. 稼働・売上・原価
| ID | 用語 | 定義 | 参照 |
|---|---|---|---|
| GLS-040 | 稼働状態 | 社員のある期間の状態。コード・名称・売上計上・給与支給率・原価計上を持つ。開発稼働／教育稼働／その他稼働／待機／社内研修／休職／育休 など | `REQ-DAT-003` |
| GLS-041 | 給与支給率 | 稼働状態ごとに決まる、月給のうち支払う割合。画面から変更できる（有効期間付き） | `REQ-DAT-003` |
| GLS-042 | 待機（減額無し／減額あり） | 売上を計上しない稼働状態。減額無しは支給率100%、減額ありは60% | `REQ-DAT-003` |
| GLS-043 | 社内研修（減額なし／減額あり） | 売上を計上しない稼働状態。減額なしは支給率100%、減額ありは60% | `REQ-DAT-003` |
| GLS-044 | 休職・育休 | 売上・原価を計上せず、支給率0%の稼働状態 | `REQ-DAT-003` |
| GLS-045 | 稼働期間 | 社員の稼働状態を、開始日と終了日で持つ記録。月の途中の切り替えにも対応する | `REQ-DAT-015` |
| GLS-046 | 稼働率 | 稼働期間ごとの稼働の割合（例：0.7、1.0）。売上の計算に使う | `REQ-DAT-015`、`REQ-CAL-010` |
| GLS-047 | 参画 | 社員の顧客・案件への参加。区分は SES／受託／既存アカプラ／教育原価。「既存アカプラ」の定義は要件定義書にない（`TBD:`） | `REQ-DAT-014` |
| GLS-048 | 単価 | 売上の計算に使う、参画に対する金額。単価履歴で有効期間ごとに持つ | `REQ-DAT-016`、`REQ-CAL-011` |
| GLS-049 | 見込み | 将来の年月ごとの売上の予測。確度（確定／高／低／待機）・見込み単価・見込み稼働率を持つ。アプリで新しく入力する | `REQ-DAT-017` |
| GLS-050 | 営業日 | 土日・祝日・会社休日を除く日。営業日カレンダーで管理する | `REQ-DAT-002` |
| GLS-051 | 営業日カレンダー | 日ごとの営業日・非営業日を持つマスタ。祝日は自動で取り込み、会社休日は画面から登録する | `REQ-DAT-002` |
| GLS-052 | 日割り | 月の途中の状態切り替えや入社・退職を、営業日数の比で按分すること | `REQ-CAL-003`、`REQ-CAL-004` |
| GLS-053 | 売上 | 売上計上○の期間の、単価 × 稼働率 × 稼働した営業日数 ÷ 当月の営業日数の合計 | `REQ-CAL-010` |
| GLS-054 | 原価 | 支払額（月給部分）× 原価係数 ＋ 月給の外の手当 ＋ 賞与（支給した月のみ） | `REQ-CAL-012` |
| GLS-055 | 原価係数 | 月給部分の原価を求める係数。現在は1.2。有効期間付きで画面から変更できる | `REQ-DAT-005` |
| GLS-056 | 粗利／粗利率 | 粗利＝売上−原価。粗利率＝粗利÷売上 | `REQ-CAL-012` |
| GLS-057 | 端数処理 | 円未満の扱い。切り上げとし、日割り・売上・原価・賞与に共通で適用する。給与は項目ごとに処理し、項目の合計を支払額とする | `REQ-DAT-005`、11章 |

## 9. 開発・実装
| ID | 用語 | 定義 | 参照 |
|---|---|---|---|
| GLS-100 | PoC | 実行できるかが不明な前提（exe 化、認証の関門、`hashlib.scrypt`、`AppTest` の限界など）を、実装の前に小さな試作で確かめること。フェーズ0（`PH-00`）で行う。コードは `poc/` に置き、製品のコードではない | 実装計画書 `IPL-002`、`IPL-030`、`IPD-006` |
| GLS-101 | 依存の固定ファイル（`locks/`） | 間接の依存を含む導入物の版を固定した、`pip freeze` の出力。`locks/` に、OS ごと・用途ごとに置く。GLS-103 のロックファイルとは別物 | 実装計画書 3.3、`IPD-003` |
| GLS-102 | 多重起動の防止 | 本アプリが同時に複数起動しないようにすること。起動時にデータ領域のロックファイルを排他的に取得し、取得できなければ起動中の旨を表示して終了する。方式は OS の排他ロック（Windows は `msvcrt.locking`、macOS は `fcntl.flock`）とする案で、PoC（`POC-06`）で確認する | アーキテクチャ設計書 5.3（`ARC-007`）、実装計画書 `IPD-007` |
| GLS-103 | ロックファイル | 多重起動の防止（GLS-102）のために、データ領域に置くファイル。存在だけでは判定せず、OS の排他ロックの取得で判定する。GLS-101 の `locks/` とは別物 | アーキテクチャ設計書 5.3（`ARC-007`）、実装計画書 `IPD-007` |
