## 1. 読み方
- 計算ルールには ID（`CLC-xxx`）を付け、要件 ID（`REQ-CAL-xxx`）と対応づける（11章）
- 要件定義書に書かれた内容は「要件」、本書で補った内容は「仕様」と区別する。要件定義書にない判断のうち、確認が必要なものは `TBD:` として残し、暫定の扱いを書く
- 次の判断は、ユーザーの回答（2026-10-21）に基づく確定事項である
  - 円未満の端数処理は、日割り・売上・原価・賞与のすべてで「切り上げ」とする
  - 給与の日割りは、給与項目ごとに端数を処理し、項目の合計を支払額とする
  - 減額が、減額順のある項目の合計を超えるときは、足りない分を基本給から差し引く
  - 評価ランクの値は `S`、`A`、`B`、`C`、`D` とする
- 数値例（9章）は、本書の仕様どおりに試作計算して確認した値である。氏名・金額はすべて架空のデータである

## 2. 共通定義

### 2.1 数値の扱いと端数処理 `CLC-001`
- 計算の途中は、誤差の出ない有理数（Python の `fractions.Fraction`）で行う。浮動小数点を使わない
- 率・係数は、データ設計書 `DBD-004` の万分率の整数を、有理数に変換して使う（10000 → 1、6000 → 3/5、12000 → 6/5）
- 円未満の端数処理は、切り上げとする。0 以上の値に対して、円未満があれば次の整数に繰り上げる
- 端数処理は、「結果として保存する金額」を求める箇所でだけ行う。箇所は次のとおり
  - 給与項目ごとの支払額（3.4）
  - 売上（4.1）
  - 月給部分の原価（5.1）
  - 賞与額（7.3）
- 減算だけで求める金額（減額、原価合計、粗利）は、整数どうしの計算なので端数処理をしない。粗利は負の値を取り得る
- 端数処理の方法は、計算設定（`system_setting`）の `端数処理` に持つ。値は `切り上げ` だけを定義する。他の方法が必要になったときは、本書を改版して追加する

### 2.2 期・半期の判定 `CLC-002`
```text
年度   = 年          （月が 4〜12）
年度   = 年 − 1      （月が 1〜3）
期     = 年度 − 2006
半期   = 上期（月が 4〜9）／ 下期（月が 10〜12 または 1〜3）
半期コード = 年度 + "-H1"（上期）／ 年度 + "-H2"（下期）
```
- 半期コードの形式は、データ設計書 `DBD-006` に従う

### 2.3 営業日 `CLC-003`
- 営業日は、営業日カレンダー（`business_calendar`）の `is_business_day = 1` の日とする
- 当月の営業日数 `D` は、当月の `is_business_day = 1` の日数とする。社員の在籍・稼働には関係しない
- `D = 0` の月は、計算しない。エラーとして一覧に出す（営業日カレンダーが未登録の月）
- 営業日は、日付の昇順に並べた集合として扱う。日付の判定は、すべて日単位で行う

### 2.4 在籍営業日 `CLC-004`
- 営業日 `b` が在籍しているとは、次の両方を満たすことをいう
  - `join_date` が `b` 以前（`join_date` が NULL の場合は、この条件を満たすものとして扱う）
  - `retire_date` が NULL、または `b` が `retire_date` 以前
- 入社日・退職日の当日は、在籍に含める。`TBD:` 要件定義書に当日の扱いの記載がなく、暫定の扱いである
- 入社・退職の月は、在籍している営業日だけで日割りする（`REQ-CAL-004`）。在籍していない営業日の支払・売上は 0 とする

### 2.5 月給合計 `CLC-005`
- 給与履歴の月給合計は、その履歴の内訳（`salary_history_item`）の `amount` の合計とする。年俸制・単価連動も同じ。`annual_salary` は計算に使わない
- ある月の月給合計 `M` は、「その月の基準日に有効な給与履歴」の月給合計とする
  - 基準日は、その月の在籍営業日のうち最後の日とする
  - 有効な履歴は、`effective_from ≦ 基準日` かつ（`effective_to` が NULL、または基準日 ≦ `effective_to`）の履歴とする
- 月の途中で給与履歴が切り替わる場合も、その月全体を基準日の履歴で計算する。`TBD:` 月途中の改定の日割りは要件定義書にない。暫定の扱いである
- 在籍営業日が 1 日もない月、または有効な給与履歴がない月は、計算しない。エラーとして一覧に出す
- `TBD:` 年俸制の月給を、内訳の合計とするか、年俸年収を 12 で割った額とするかは、要件定義書に明記がない。要件定義書 5.2 の「月給合計は内訳の合計で計算する」に従い、内訳の合計とする

## 3. 給与支払額・減額

### 3.1 入力 `CLC-006`
社員 1 人・1 か月ごとに、次を入力として計算する。

| 入力 | 内容 |
|---|---|
| `M` | 月給合計（2.5） |
| 内訳 | 基準日に有効な給与履歴の内訳（給与項目ごとの金額）と、給与項目の `deduction_order`・`sort_order` |
| `D` | 当月の営業日数（2.3） |
| 在籍営業日 | 当月の営業日のうち、在籍しているもの（2.4） |
| 稼働期間 | 当月に重なる稼働期間と、その稼働状態 |
| 支給率 | 稼働状態ごとの給与支給率（有効期間付き） |

### 3.2 日割りの支払額（端数処理前） `CLC-007`
```text
営業日 b の支給率 r(b):
  b が在籍営業日でない場合            → 0
  b を含む稼働期間がない場合          → 3.6 の扱い
  b を含む稼働期間がある場合          → その稼働状態の、b に有効な給与支給率

支払額（端数処理前） P_raw = Σ（当月の営業日 b） M × r(b) ÷ D
減額（端数処理前）   X_raw = M − P_raw
```
- これは、要件定義書 6.2 の「Σ（状態ごとの期間）月給合計 × 支給率 × 該当期間の営業日数 ÷ 当月の営業日数」を、営業日単位で書き下したものである（`REQ-CAL-003`）
- 期間の途中で支給率の有効期間が切り替わる場合も、営業日ごとに支給率を決めるので、同じ式で扱える

### 3.3 減額の配分 `CLC-008`
減額（端数処理前）`X_raw` を、給与項目に次の順で配分する（`REQ-CAL-006`）。

```text
差し引く順 =
  （1）減額順（deduction_order）のある項目を、減額順の小さい順
  （2）減額順のない項目を、表示順（sort_order）の小さい順

残り = X_raw
各項目 i を差し引く順に:
  差引_i = min(項目 i の金額, 残り)
  残り   = 残り − 差引_i
  支払_i（端数処理前） = 項目 i の金額 − 差引_i
最後に 残り = 0 になる（X_raw ≦ M のため）
```
- 初期データでは、減額順は リーダー手当 → 資格手当 → その他手当 → 一時手当（毎月） → 役職手当 → 住宅手当 → 固定残業手当 の順である
- 減額順のない項目は、初期データでは基本給（表示順 1）と勤務手当（職務給）（表示順 2）である。減額順のある項目で足りない分は、基本給から差し引く（確定事項）
- `TBD:` 基本給でも足りない場合は、表示順に従って次の減額順のない項目（勤務手当）から差し引く。要件定義書とユーザー回答に記載がなく、暫定の扱いである（休職・育休の月で起きる）
- `0 ≦ X_raw ≦ M` が成り立つ条件は、すべての支給率が 0 以上 1 以下であること。支給率が 1 を超える設定は、画面で登録できない扱いとする（画面設計書 10章で定めた：給与支給率は 0〜100% のみ登録できる（`SCN-061`）。暫定。ユーザーの確認待ち）

### 3.4 項目ごとの端数処理と支払額 `CLC-009`
```text
支払_i  = ceil(支払_i（端数処理前）)               … 項目ごとの支給額（monthly_payroll_item.paid_amount）
減額_i  = 項目 i の金額 − 支払_i                    … 項目ごとの減額（monthly_payroll_item.deduction_amount）
支払額 P = Σ 支払_i                                 … monthly_payroll.paid_amount
減額   X = M − P                                    … monthly_payroll.deduction
```
- 項目の金額は整数なので、`減額_i` も整数になる。端数は、支払が円未満の端数を持つ項目だけが切り上げられる
- 減額順に従って差し引くと、端数を持つ項目は、差し引きの境目にある 1 項目だけである。このため、`Σ ceil(支払_i)` は `ceil(P_raw)` と一致する（乱数による 20,000 ケースの試作計算でも一致を確認した。試験でも確認する：`TC-CLC-010`）
- `M`（月給合計）は `monthly_payroll.monthly_salary` に保存する

### 3.5 正誤判定 `CLC-010`
- `M = P + X` が成り立たなければ「要確認」、成り立てば「OK」とする（`REQ-CAL-007`）
- 3.4 の定義では `X = M − P` なので、この判定は常に「OK」になる。要件定義書 6.2 に従って実装するが、判定が意味を持つ場面（要件の意図）は確認が必要（12章 No.16）
- 「要確認」になるのは、この判定ではなく、3.6 の稼働状態が未設定の営業日がある場合である（暫定の扱い）
- 人事連携用の出力でも、同じ判定結果（`check_result`）を使う

### 3.6 稼働状態が未設定の営業日 `CLC-011`
- 在籍営業日のうち、稼働期間に含まれない日がある月は、`check_result` を「要確認」とする。支払額は、その日の支給率を 0 として計算する
- `TBD:` 要件定義書に、稼働期間が未設定の日の扱いの記載がない。上記は暫定の扱いであり、確認が必要
- 同じ社員の稼働期間は重ならない前提とする（データ設計書 10章 No.2）。重なる場合はエラーとして一覧に出す

## 4. 売上

### 4.1 売上の計算 `CLC-012`
```text
対象の営業日 b = 在籍営業日で、売上計上（is_billable）が ○ の稼働期間に含まれる日
売上 = ceil( Σ（対象の営業日 b） 単価(b) × 稼働率(b) ÷ D )
```
- 稼働率は、b を含む稼働期間の `billing_ratio_bp`（万分率）を有理数に変換して使う
- これは、要件定義書 6.3 の式を営業日単位で書き下したものである（`REQ-CAL-010`）
- 売上は、社員・月ごとの合計に対して、端数処理を 1 回だけ行う。`TBD:` 稼働期間ごとに端数処理をするかは、要件定義書にない。暫定の扱いである
- 売上計上が × の状態の営業日は、売上に含めない

### 4.2 単価の決定 `CLC-013`
営業日 `b` の単価は、次の順で決める（`REQ-CAL-011`）。

```text
（1）b を含む稼働期間の assignment_id について:
     単価履歴のうち、同じ assignment_id で effective_from ≦ b の行の、effective_from が最大のもの
（2）（1）がない場合（稼働期間に assignment_id がない場合を含む）:
     単価なし
```
- 期間の途中で単価が改定されても、営業日ごとに単価を決めるので、同じ式で扱える
- 売上計上が ○ の営業日に単価がない場合は、その社員・月を計算しない（給与・売上・原価とも保存しない。8章）。エラーとして一覧に出す（ユーザー回答 2026-10-26。12章-7 は解決済み）。単価がない案件は、単価に 0 を登録する運用とする。単価 0 は正しい単価として扱い、売上 0 で計算する

## 5. 原価・粗利

### 5.1 原価 `CLC-014`
```text
原価係数 c   = 月の初日に有効な計算設定（原価係数）
月給部分の原価 cost_salary = ceil( Σ（in_monthly_salary = 1 の項目 i） 支払_i × c )
月給の外の手当 cost_allowance = Σ（cost_direct = 1 の項目 i） 支払_i
賞与           cost_bonus     = 当月が支給月で、確定済み（is_closed = 1）の賞与の bonus_amount の合計
原価合計       cost_total     = cost_salary + cost_allowance + cost_bonus
```
- 原価は、3.4 の項目ごとの支払額を使い、給与の計算と同時に計算し直す（`REQ-CAL-009`、`REQ-CAL-012`）
- 賞与には原価係数を掛けない（`REQ-CAL-013`）。賞与は、支給した月（`pay_month`）の原価にだけ計上する（`REQ-CAL-021`）
- `in_monthly_salary = 0` かつ `cost_direct = 0` の項目は、原価に含めない
- `TBD:` 月の途中で原価係数が切り替わる場合は、月の初日に有効な値を、その月全体に使う。暫定の扱い
- `TBD:` 稼働状態の「原価計上」が × で、支給率が 0 でない設定は、扱いが要件定義書にない。初期データでは、原価計上が × の状態は支給率 0 で、影響しない。このため、本書の計算は支払額だけから原価を求める

### 5.2 粗利・粗利率 `CLC-015`
```text
粗利     gross_profit = sales − cost_total          … 整数。負の値を取り得る
粗利率   = gross_profit ÷ sales                      … sales が 0 のときは算出しない
```
- 粗利率は、保存せず、表示・集計のときに計算する。表示の桁数は、画面設計書 10章で定めた：小数第1位まで、四捨五入、売上が 0 のときは `－`（`UID-041`、`UID-071`。暫定。ユーザーの確認待ち）
- 半期・期の粗利率は、期間内の売上の合計と粗利の合計から計算する。月ごとの粗利率の平均にはしない

## 6. 昇給

### 6.1 昇給額 `CLC-016`
```text
昇給額 = その履歴の月給合計 − 直前の履歴の月給合計
```
- 昇給額は、保存せず、一覧の表示のときに計算する（`REQ-DAT-009`）
- 最初の履歴（入社など、直前の履歴がないもの）には、昇給額を表示しない

### 6.2 改定の登録 `CLC-017`
- 新しい給与履歴を登録するとき、直前の履歴（`effective_to` が NULL のもの）の `effective_to` を、新しい履歴の `effective_from` の前日に設定する（`REQ-CAL-015`）
- 直前の履歴の `effective_from` が、新しい履歴の `effective_from` 以後の場合は、登録できない（エラー）

### 6.3 改定月の警告 `CLC-018`
次の組み合わせに当てはまらない改定の登録では、警告を出す。登録は拒否しない（`REQ-CAL-016`）。

| 給与体系 | 警告を出さない `effective_from` の月 |
|---|---|
| 通常評価制度 | 4月、10月 |
| 年俸制 | 4月 |

- 改定区分が `入社` と `制度移行` の登録には、警告を出さない。`TBD:` 要件定義書は「決まった月以外に改定を登録しようとしたら警告」とだけ記載している。上記の除外は暫定の扱い
- 単価連動（19期のみ）には、警告の対象月を定めない（`TBD:`）

## 7. 賞与

### 7.1 支給月・基準月 `CLC-019`
| 査定対象の半期 | 支給月 | 基準額を取る月 |
|---|---|---|
| 上期（`YYYY-H1`） | `YYYY` 年 10 月 | `YYYY` 年 9 月 |
| 下期（`YYYY-H2`） | `YYYY + 1` 年 4 月 | `YYYY + 1` 年 3 月 |

- 要件定義書 6.6 の表（`REQ-CAL-019`）を、半期コードで書き下したものである

### 7.2 対象者と基準額 `CLC-020`
- 賞与の対象は、通常評価制度の在籍者とする。年俸制は対象外（`REQ-CAL-018`）
  - 通常評価制度かどうかは、基準月の基準日（2.5）に有効な給与履歴の `pay_system` で判定する
  - `TBD:` 「在籍者」を判定する日と、在籍ステータスの範囲（`在籍`・`退職予定` を含めるか）は、要件定義書にない。暫定として、支給月の初日に `retire_date` が NULL、または支給月の初日以後である社員とする
- 基準額 `base_amount` は、賞与ルール（`bonus_rule`）の `base_type` に従う（`REQ-CAL-020`）
  - 賞与ルールは、支給月の初日に有効なものを使う
  - `基本給`：基準月の基準日に有効な給与履歴の内訳のうち、区分（`category`）が `基本給` の項目の金額の合計
  - `月給合計`：基準月の月給合計 `M`（2.5）
- 基準月に在籍営業日がない社員（基準月より後の入社など）は、基準日を決められないため、賞与の対象にしない。`TBD:` 要件定義書に記載がなく、暫定の扱いである（12章-19）
- 対象者の判定は、支給済みの賞与の手入力にも適用する（画面設計書 `SCN-040`。ユーザー承認 2026-10-27）
- 基準額は、減額・日割り前の金額（給与履歴の金額）を使う。`TBD:` 要件定義書 5.2 の `monthly_salary` の定義（その月に有効な月給合計）に基づく解釈であり、確認が必要

### 7.3 賞与額 `CLC-021`
```text
賞与額 bonus_amount = ceil( base_amount × 掛け率 )
```
- 掛け率は、評価（`evaluation`）の評価ランクと、掛け率（`bonus_rate`）の `(eval_half, eval_rank)` から決める（`REQ-CAL-017`）
- 評価ランクの値は `S`、`A`、`B`、`C`、`D` とする。掛け率の値は画面から登録する（要件定義書 12章-1 の未決事項）
- 評価が未入力、または掛け率が未登録の社員は、賞与を計算しない。画面で未入力として一覧に出す
- 計算した掛け率は、`bonus.rate_bp` に複写して保存する。後から掛け率を変更しても、計算済みの賞与は変わらない
- 賞与を確定（`is_closed = 1`）すると、その賞与は支給月の原価に反映する（5.1）

## 8. 再計算と締め `CLC-022`
- 再計算の対象は、締め前の月に限る。締め済みの月は、再計算しない（`REQ-CAL-008`）
- 再計算のきっかけは、給与履歴・稼働期間・稼働状態マスタ（支給率を含む）・営業日カレンダーの変更である（要件定義書 6.2）。これに加えて、計算結果に影響する次のデータの変更も、きっかけとする（本書での補足。`TBD:` 要件の意図の確認が必要）：給与項目、原価係数、単価履歴、賞与の確定。さらに、社員の入社日・退職日（在籍営業日が変わる）と、参画の区分（`monthly_pl.category` が変わる）の変更も、きっかけとする（PH-10-4 の実装での補足）。給与項目の追加は、まだどの給与履歴にも使われないため、きっかけとしない。賞与の確定には、支給済みの賞与の手入力（確定済みとして登録）を含める（ユーザー承認 2026-10-27）
- 処理方式は、アーキテクチャ設計書 `ARC-009` に従う
- 1 社員・1 か月の計算結果は、`monthly_payroll`、`monthly_payroll_item`、`monthly_pl` を、同じトランザクションで保存する
- 計算のエラー（2.3、2.5、3.6 の稼働期間の重なり、4.2、5.1 の原価係数が未設定）が出た社員・月は、結果を保存せず、エラーの一覧に出す。他の社員・月の計算は続ける
  - 前回の計算結果があるときは、消さずに残す（人事連携の入力 `hr_target`・`hr_note` を失わないため）。エラーの一覧は、保存せず、画面を開くたびに判定し直す
  - 再計算の対象の社員は、その月に在籍期間（入社日〜退職日）がかかる社員とする
- 更新のあとに再計算する月（影響する月）は、変更の影響する日付の月以降で、計算済み（その月の `monthly_payroll` が1件以上ある）かつ締め前の月とする（ユーザー回答 2026-10-26）。社員ごとのデータ（社員・給与履歴・稼働期間・参画・単価）の変更は、その社員だけを、マスタ（営業日カレンダー・支給率・給与項目・原価係数）の変更は、全社員を再計算する。まだ一度も計算していない月は、`SCN-032` の再計算で計算する
- 再計算は、`monthly_payroll` の `hr_target`・`hr_note` を上書きしない（画面設計書 `UID-075`）。`monthly_payroll_item` は、給与履歴の項目が変わりうるため、作り直す
- `monthly_pl` は、`source` を `再計算` として保存する。`source` が `取込` の行と、締め済みの行は上書きしない。`category` は、売上計上の最後の在籍営業日の参画の区分とする。売上計上の日がない月は空とする（暫定。データ設計書 13章-10）
- 計算順は次のとおり

```text
1. 営業日数 D と、在籍営業日を求める（2.3、2.4）
2. 月給合計 M と内訳を求める（2.5）
3. 営業日ごとの支給率から、P_raw と X_raw を求める（3.2）
4. 減額を項目に配分し、項目ごとに端数処理して、支払額 P・減額 X を求める（3.3、3.4）
5. 正誤判定を行う（3.5、3.6）
6. 売上を求める（4.1、4.2）
7. 原価・粗利を求める（5.1、5.2）
```
